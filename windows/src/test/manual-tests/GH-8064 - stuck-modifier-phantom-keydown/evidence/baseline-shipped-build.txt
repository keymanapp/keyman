=== GH-8064 baseline, shipped build - measured 2026-08-29 ===

The defect, reproduced 5 of 5 on an unmodified released Keyman. This is the
proof-of-bug half. The matching run against this branch is
evidence/run-after-branch-2026-08-29.txt, which states the confounds between
the two.

--- what was installed ---

Official Keyman 19.0.276, from a clean installer run. Not a swapped file:

  keyman32.dll   1,239,488 bytes  v19.0.276.0   Release
  keyman64.dll   1,369,024 bytes  v19.0.276.0   Release
  kmshell.exe                     v19.0.276.0

--- preconditions, every one of which had to hold ---

Host        host32.exe, verified 32-bit. serialkeyeventserver.cpp is #ifndef _WIN64,
            so the modifier cache under test does not exist in a 64-bit process.
            Windows 11 Notepad is 64-bit -- both notepad.exe and SysWOW64\notepad.exe
            report IsWow64Process false -- which is why this host exists.

Keyboard    k_0301___multiple_deadkeys, selected in the host window and confirmed
            firing before any measurement began. "1x2x3x" -> "1=OK 2=OK 3=OK ".
            No Shift is involved in that transform, which matters, because Shift is
            the modifier under test.

Logging     Engine logging off.

Elevation   host32 NOT elevated. Keyman runs as the user, and UIPI stops a
            lower-integrity process's low level hook from seeing input destined for a
            higher-integrity window. An elevated host would assemble no batch and
            report a clean PASS for the wrong reason.

--- command ---

  host32.exe --fakefreeze <fakefreeze.exe> --probe 1x2x3x --iterations 5 --wait-for-rule 30

--- run ---

  --- iteration 1 of 5 ---
      freeze active: yes
      modifier released (inside the stall)
      typed "1x2x3x" -> got "1=OK 2=OK 3=OK "  transformed: yes
      [FAIL] stuck: SHIFT, LSHIFT
  --- iteration 2 of 5 ---   ... identical ...   [FAIL] stuck: SHIFT, LSHIFT
  --- iteration 3 of 5 ---   ... identical ...   [FAIL] stuck: SHIFT, LSHIFT
  --- iteration 4 of 5 ---   ... identical ...   [FAIL] stuck: SHIFT, LSHIFT
  --- iteration 5 of 5 ---   ... identical ...   [FAIL] stuck: SHIFT, LSHIFT

  iterations 5   freeze confirmed 5   text transformed 5   stuck 5
  RESULT: FAIL - the defect reproduced. A modifier was held with nothing pressed.

--- why this is a measurement and not a coincidence ---

freeze confirmed 5/5 and text transformed 5/5. Both had to hold. The freeze is
confirmed live rather than assumed after a fixed delay, so the modifier release
genuinely landed inside the stall. The transform proves a batch was actually
assembled, so keybd_shift_reset genuinely ran.

An earlier attempt the same day returned INCONCLUSIVE with "text transformed 0":
five iterations, no modifier stuck, and it proved nothing, because no Keyman rule
fired and no batch was ever built. The harness refused to call that a pass. That
refusal is what makes both halves of this pair meaningful.
